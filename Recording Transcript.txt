FITLORE RESCUE — RECORDING TRANSCRIPT
Target: 4 minutes 40 seconds. Hard maximum: 5 minutes.
Use your own voice. Read these as talking points, not a polished advertisement.

BEFORE RECORDING (not narrated)
1. Open http://127.0.0.1:8033 in a wide browser window. Keep text readable.
2. Open the Google Doc report, public GitHub repository and this Codex conversation in separate tabs.
3. In the app select Shoot workspace > Fictional demonstration, Scenario > Missing hero jacket, Run mode > Live AI agent. Do not click Investigate yet.
4. Practice without paid calls: use Rehearsal mode, then switch back to Live AI before recording. The rehearsal label must never be presented as a live model result.
5. Locate saved investigations “Evaluate retry” and “Evaluate no_match” beforehand so you can find them quickly. Return to the fictional demonstration and Live AI mode.
6. Have app/agent.py and tests/test_workspace.py available in your editor. Show source and tests, never .env or credentials.
7. Record screen and microphone. An optional small webcam view is fine. Avoid generated voice, avatar, background music and elaborate transitions.
8. Nine model requests remain within the authorized cap. The standard evaluation used five calls; real runs can differ. Record one fresh live run. Do not retry repeatedly if it fails.
9. Pause notifications and check microphone audio. Start a timer. The timings below are pacing targets, not instructions to pretend a slow run finished.

SCREEN: App brief and blocked looks. Point at G01 and the two affected looks.
SAY:
“This is FitLore Rescue. I’m building it for a stylist whose shoot is almost ready when an important garment becomes unavailable. Here, the same navy jacket is used in two looks. The replacement needs to match the brief, arrive before the ten o’clock call, and stay within sixty dollars. This is a custom use case, demonstrated with fictional wardrobe data.”

SAY:
“The shoot can be edited, and wardrobe records can be imported from CSV. So the workflow isn’t limited to this example. For this recording, I’m keeping the prepared brief so we can follow the result clearly.”

Then scroll to Does the workflow finish the job?, confirm whether the revised plan is usable, add a short factual note and click Record outcome assessment. ACTION: Show the public repository and Google Doc, then return to the completed live run if time allows.

The code and project report are linked in my submission.”

IF SOMETHING FAILS
- State what is actually displayed. A safe handoff is a legitimate result; do not conceal it with a rehearsal result.
- A saved successful trace can explain behavior, but label it saved. The recording must still show an actual live application attempt and its true result.
- If the model request allowance is exhausted, do not change the cap or claim a replay is live. Ask for additional authorization before another paid run.
- If nearing five minutes, shorten input editing and the closing paragraph. Keep live result, human approval/handoff, failure evidence and AI coding-tool usage.

AFTER RECORDING
Trim only dead time at the beginning/end. Keep the investigation and approval sequence honest and continuous. Verify total length <=5 minutes, audible voice, readable text and reviewer access to the video link. Submit the video link, Google Doc and GitHub repository using the handout’s submission form.
